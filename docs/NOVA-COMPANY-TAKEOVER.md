# Nova Company Takeover

## Purpose

XX is the canonical company-replication/takeover package for the owned **AI Business Factory**. It packages the existing company operating system so Nova can operate it as one governed system instead of rebuilding disconnected pieces.

## Operating authority

Nova uses the existing Boss/Governor control plane, mission kernel, workforce controller, connector manager, memory and learning loops. XX does not create a second controller.

## Takeover sequence

1. Load this canonical manifest as Nova's company context.
2. Verify source repository, AI Business Factory project identity and production version.
3. Hydrate Boss/Governor/mission/workforce state from the existing control plane.
4. Load the program inventory, API surfaces, libraries, data planes and tool registry.
5. Reconcile connector/tool readiness without self-granting permissions.
6. Resume the existing governed schedules, queues and worker loops.
7. Use the existing product, acquisition, revenue, growth, fulfillment and learning loops as one company.
8. Persist evidence and lessons back into Nova memory and company state.
9. Keep Nova as the operating owner of the replicated company system; do not create a competing controller.

## External tool boundary

The manifest records tool capabilities and readiness, but never embeds credentials. Existing provider authorizations, device pairing, account permissions and paid-spend approvals remain subject to their existing security boundaries.

For external companies/services, Nova may reproduce publicly observable functionality independently; the package does not authorize copying proprietary code, private data, credentials or protected branding.
